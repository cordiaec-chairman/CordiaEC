# 반(反)프랑켄슈타인 아키텍처 감사 체크리스트 (Anti-Frankenstein Audit Protocol)

## 1. 개요: 소프트웨어의 프랑켄슈타인 현상이란?
초기에는 가볍고 명확했던 소프트웨어가 고객 요청이나 신규 아이디어가 누적되면서, **"본래의 뼈대와 엔진을 리팩터링하지 않고 겉면에 새 부품을 덕지덕지 이어 붙여(Additive Patching)"** 점점 느려지고, 기괴해지며, 본래의 핵심 가치가 훼손되는 현상을 말합니다.

본 감사는 모든 신규 기능이 추가될 때마다 **"이 기능이 본체에 기생하여 숙주를 병들게 하고 있지 않은가?"**를 기계적으로 진단하는 영구 방어선입니다.

---

## 2. 5대 프랑켄슈타인 징후 진단표 (The 5 Pathology Signals)

### 징후 1. 주객전도 (Feature Creep / Host Eclipse)
- **증상**: 부가 기능(조연)의 안내 문구, 배너, 모달이 메인 기능(주연)의 시각적 면적이나 인지적 주의력을 50% 이상 잠식함.
- **감사 기준**:
  - [ ] 메인 작업 화면에 진입했을 때, 신규 기능의 시각적 점유 면적이 25% 이하인가?
  - [ ] 신규 기능의 존재를 모르는 유저가 화면을 보았을 때 본래 목적 달성 버튼을 1초 안에 찾을 수 있는가?

### 징후 2. 전역 상태 거대화 및 얽힘 (State Entanglement)
- **증상**: 신규 기능만을 위해 생성된 로컬 상태(임시 선택값, 팝오버 좌표 등)가 부모 컴포넌트나 전역 스토어(Redux, Zustand, React Context)의 루트 레벨을 오염시킴.
- **감사 기준**:
  - [ ] 신규 기능의 상태가 언마운트 시점에 완전히 가비지 컬렉션(GC)되는가?
  - [ ] 신규 기능 컴포넌트가 런타임 에러(Crash)를 일으켰을 때, `ErrorBoundary`에 의해 안전하게 격리되고 메인 컴포넌트는 죽지 않고 살아남는가?

### 징후 3. 뷰포트 레이어 및 z-index 전쟁 (Layout & Layer Pollution)
- **증상**: 새 팝오버나 툴팁을 띄우기 위해 `z-[99999]`, 강제 `relative`, 인라인 스타일 등을 남발하여 기존 모달의 중앙 정렬을 무너뜨리거나 스크롤 락을 파괴함.
- **감사 기준**:
  - [ ] Radix UI, Headless UI 등의 다이얼로그 내부에서 띄우는 플로팅 엘리먼트가 `DialogContent` 내부에 마운트되어 포커스 트랩과 충돌하지 않는가?
  - [ ] 신규 레이어가 닫힌 후 `document.body`의 `overflow: hidden`이나 `pointer-events` 속성이 잔류하지 않는가?

### 4. 페이로드 덧대기 및 데이터 오염 (Payload Mutation Leak)
- **증상**: 새 기능의 저장 버튼을 눌렀을 때, 백엔드로 전송되는 페이로드에 기존 데이터 필드가 누락되거나 의도치 않은 기본값(null, 빈 문자열)으로 덮어씌워짐.
- **감사 기준**:
  - [ ] 신규 저장 액션이 기존 릴레이션 및 비수정 컬럼의 체크섬(Checksum)을 100% 보존하는가?
  - [ ] 롤백(Rollback) 및 복구 경로가 보장되는가?

### 5. 근육 기억 파괴 (Muscle Memory Disruption)
- **증상**: 수개월간 '클릭 한 번'으로 저장하던 버튼의 위치가 신규 기능 버튼에 밀려 옆으로 이동했거나, 클릭 시 "정말 저장하시겠습니까? (새 기능도 함께 실행할까요?)" 같은 확인 모달이 끼어듦.
- **감사 기준**:
  - [ ] 기존 단축키(예: Cmd+Enter, Esc)의 기본 동작이 신규 기능의 단축키와 충돌하지 않는가?
  - [ ] 기존 핵심 액션의 스텝 수가 단 1스텝도 늘어나지 않았는가?
